# Robo 2.0：从"索引"到"工作台"——功能设计与优先级

> 日期：2026-09-18 | 起因：Eric 判断"目前 Robo 太单薄" | 性质：设计稿，等拍板后分批实施

## 0. 先说清楚为什么单薄

今天的 Robo 有：40 个开源 VLA 模型、12 个机器人本体、6 种显卡、96 格模型×本体适配状态、15 条我们自己跑出来的推理实测（4090 / 5090 / A800）。每个字段带来源，中英双语，有榜单、筛选器、对比、矩阵。

问题不在"少"，在"死"：

1. **内容是静态快照。** 除了我们手动加模型，站点每天不变。用户第二次来看到的和第一次一样，没有回访理由；订阅了也没东西可发。
2. **只回答了第一层问题。** 开发者的三层问题是：有哪些（我们答了）→ 在我的条件下怎么样（只答了一点：显存估算、少量实测）→ 具体怎么做（没答）。第二、三层才是真正花时间的地方。
3. **用户只能看，不能算、不能做、不能参与。** 没有一个入口让人输入自己的条件得到答案，也没有一个入口让人把自己的结果贡献回来。Compute 之所以有人用，是因为它每天在变、能算价格、能众测；Robo 三样都还没有。

流量证据：过去两周 Robo 真人会话约 25 次，看得最多的是模型详情页，其次首页和本体页。人是为"具体某个模型的情况"来的，不是为榜单来的。

## 1. 设计原则（延续 Sinan 的做法）

- **只做能自动更新的。** 每一项都要回答"以后谁来维护"，答案必须是脚本，不是人。
- **每个数字有来源、有日期。** 分数写"论文口径"就是论文口径，不做跨论文的综合分。
- **不打分、不推荐。** 排序只按事实字段；措辞过同一套禁用词检查。
- **中文区独有的信息优先。** 国内镜像可得性、国内租卡价格、国内数据集、中文部署踩坑，这些英文站没有，才是我们的差异。
- **先用已有的资产。** bench/ 里五个能跑通的适配器、AutoDL 价格账本、Compute 的众测与订阅机制，都能直接复用。

## 2. 功能清单（按优先级）

### A. 活性信号——让站点每天自己变（P0，全自动，零成本，1–2 天）

每天抓一次，写进模型数据：

| 来源 | 字段 | 用途 |
|---|---|---|
| GitHub API | stars、forks、最近一次提交、近 90 天提交数、未关闭 issue 数、最新 release | "还在维护吗" |
| Hugging Face API | 近 30 天下载量、likes、权重最后更新时间、权重文件是否变动 | "有人在用吗、权重换过没" |
| ModelScope API | 同名模型是否有国内镜像、镜像更新时间 | "国内下得下来吗" |

产出：
- 模型页新增"活性"卡（四个数字 + 30 天走势小图）。
- 榜单新增"近 90 天最活跃"和"超过 180 天无提交"两榜（后者只陈述事实，不下结论）。
- **周报自动生成**：本周新增模型、权重更新、许可证文本变化、停更预警、实测新增；直接接 Compute 的订阅邮件与 /social.xml 渠道。这一条解决"订阅了没东西发"。

验收：40 个模型全部有活性字段，每日更新，周报连续发出 4 期。

### B. 频率与成本工作台——让用户能算（P0，用已有实测，零成本，1 天）

把 /select 从"筛选表"升级成"输入条件得答案"：

- 输入：本体、显卡（含 AutoDL 国内价与海外价）、目标控制频率（如 5 Hz / 10 Hz）、每天运行小时数。
- 输出：哪些模型的 p95 延迟满足 1000 ms ÷ 频率；每千次推理成本；按天/按月成本；没有实测的模型标"未测"，不估。
- 每个数字点开看实测记录（机器、精度、日期、脚本版本）。

验收：4090 / 5090 / A800 三卡的 5 个模型能全部算出；页面明确区分"实测"与"未测"。

### C. 部署配方与环境坑位表——让用户能做（P0，写一次长期有效，零成本，2 天）

bench/ 里五个适配器是我们已经踩平的路：transformers 版本互相冲突（4.40 / 4.47 / 4.57）、lerobot 要单独环境、hf-mirror 的 Xet 要关、SpatialVLA 缺 scipy、MolmoAct 缺 einops 且要指定注意力实现、5090 要 torch 2.8。把它们变成页面：

- 每个模型一页"在 X 卡上跑 Y"：环境、权重（含国内镜像命令）、依赖版本、一条运行命令、实测延迟、常见报错与修法。
- 一张"环境坑位表"：模型 × transformers/torch 版本 × 额外依赖 × 已知问题。
- 全部命令来自 bench/，脚本更新页面跟着更新。

验收：首批 5 篇（SmolVLA / OpenVLA / SpatialVLA / NORA / MolmoAct），每篇的命令在 AutoDL 新机器上 30 分钟内跑通。

### D. 基准分数表（P1，一次录入 1–2 天，之后每月增补）

收录 LIBERO、SimplerEnv、CALVIN、VLABench、RoboArena 等公开分数：基准名、任务集、分数、来源类型（论文 / 官方仓库 / 第三方复现）、日期、链接。

- 只列，不合成；同一基准下可排序，跨基准不比较。
- 模型页新增"公开分数"卡；榜单新增按基准分榜（每榜注明口径）。

验收：≥ 25 个模型至少有一项分数；每个分数两步内到原文。

### E. 数据集索引（P1，2–3 天，规模字段可自动更新）

模型索引没有数据集索引是半张图——能不能微调到自己的本体，取决于有没有数据。

- 收录 LeRobot 社区数据集、Open X-Embodiment、DROID、AgiBot World、RoboMIND、Galaxea Data Hub 等。
- 字段：本体、小时数 / 轨迹数、任务数、许可证、格式（LeRobot v3 等）、国内镜像。
- 与本体页联动："这个本体有多少公开数据可用"；与模型页联动："这个模型的预训练用了哪些"。

验收：≥ 30 个数据集；12 个本体每个至少能看到可用数据量（含"暂无"）。

### F. 边缘硬件实测——Jetson（P1，需要预算）

机器人真实部署在 Jetson Orin / Thor 这类板子上，不在 4090 上。我们现在的实测是"开发机口径"，不是"部署口径"。

- 方案一：买一块 Jetson Orin Nano Super 开发套件（约 ¥2,000），常驻实测，一次投入长期用。
- 方案二：众测（见 G），等有人贡献。
- 有了 Jetson 数据，B 的工作台才能回答"上机以后到底几 Hz"。

需要 Eric 决定是否投入。

### G. 众测 CLI（P2，3–4 天，价值随用户数增长）

把 bench/ 打包成 `pip install sinan-robo`，一条命令在本地显卡测某模型并可选上传。复用 Compute 众测的全部规则：匿名、同机同配置 24 小时去重、离中位数太远进待审、只传指标与硬件指纹不传图像。

### H. 复现记录（P2，依赖 G 带来的用户）

用户提交"模型 × 本体：跑通 / 需微调 / 没跑通"+ 日志链接，矩阵格子从"厂商声明"升到"社区复现"。这是 96 格矩阵变厚的唯一可持续路径。

### I. 月度《开源 VLA 观察》（P1，与 Compute 月报同机制）

自动结构块（新增 / 更新 / 停更 / 许可证变化 / 实测新增 / 数据集新增）+ 分析与判断。首期可与《开源具身模型推理成本基准 · 第一期》合并发布。

## 3. 推荐顺序

| 批次 | 内容 | 花钱 | 人工 | 效果 |
|---|---|---|---|---|
| 第一批（本周） | A 活性信号 + B 工作台 + C 部署配方 | 0 | 全自动 / 写一次 | 站点每天变；用户能算、能做；周报有料 |
| 第二批（下两周） | D 分数表 + E 数据集 + I 月报 | 0 | 一次录入 + 自动增补 | 内容厚度翻倍；可被引用 |
| 第三批（看条件） | F Jetson + G 众测 CLI + H 复现记录 | F 约 ¥2,000 | 中 | 从"我们测"变"大家测" |

## 4. 需要 Eric 拍板的

3. F：要不要花约 ¥2,000 买一块 Jetson Orin Nano Super。
